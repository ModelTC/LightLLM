PD 分离的 Prefill 先推理模式

Decode 仍然用 radix cache，命中的前缀不传。满匹配时也让 prefill 把预留的最后一个 token 传过来，首 token 挂在这最后一块上。不再走「不传页、decode 自己采样」。图中的 PD_PF_PREFILL_REQ、PD_PF_PREFILL_KV_READY、PD_PF_DECODE_KV_READY 只用于这个模式。PF 是 PREFILL_FIRST 的简写。

满匹配也传最后那个 token。 老模式在 ready_kv_len == input_len - 1 时不传页，放一个 0 长度任务，让 decode 自己采样。新模式仍用 radix，但这个长度也建成真实页，由 prefill 发送。首 token 写在最后一块的 done 上。

三方都还在

中止用现有的 ABORT。Prefill 和 decode 收到的是同一条命令。首 token 已经返回之后不再重新 prefill，只放页并把这条流以错误结束。

消息丢了，或某一侧已经不在

ABORT 送不到时，prefill 由本节点 httpserver 等端点超时后自己 abort，decode 靠现有传输超时退出。会话进了失败之后，晚到的 PD_PF_PREFILL_KV_READY、PD_PF_DECODE_KV_READY 和 upkv 都丢掉。

场景谁还占着资源怎么退出
Prefill 已算完并占住 KV，ABORT 没送到，或 master 已经不在 Prefill 的 KV。传输任务还没建立，任务超时不会开始 Prefill 的 httpserver 等 PD_PF_DECODE_KV_READY 超时后调用 abort。推理进程看到 infer_aborted 后，即使还挂着 pd_wait_decode_kv_info_ready 也不再拦住，下一轮现有结束路径回收 KV
Decode 的任务已进 waiting_dict，WRITE 没来 Decode 上还没分到目的页的任务 现有传输超时，大约 180 秒后失败并归还这些页。已经分到目的页的任务仍走完原来的收尾
P 或 D 连向 master 的某条 websocket 断了 这条连接上还登记着的请求。同一节点上其他连接的请求不动 这条连接的处理循环退出前，对这些请求做和收到 ABORT 相同的释放。推理进程看到 infer_aborted 后放开 KV
Decode 进程退出，注册用的 websocket 断开，或 30 秒没有心跳 Prefill 的 KV。Decode 的显存随进程消失 Master 同样在连接处理的 finally 里 remove_pd，把请求标成错误，再向 prefill 发 ABORT。ABORT 没送到时，prefill 的 httpserver 等端点超时后自己 abort。连接没断时 master 不知道进程状态
Prefill 进程退出，注册用的 websocket 断开，或 30 秒没有心跳 Decode 上已经占下的页。Prefill 的显存随进程消失 Master 的连接处理在 finally 里调用 remove_pd，把用这条连接的请求标成错误，再向 decode 发 ABORT。连接没断时 master 不知道进程状态，decode 靠传输超时归还页
