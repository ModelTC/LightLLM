已知使用约束
============================

本页记录当前版本已确认并接受的使用约束，作为接口支持边界维护，不作为待修复 bug 跟踪。
使用对应底层接口时，调用方需要遵守这些约定。

PD 分段续跑中的自定义思考结束标记
------------------------------------------------------------

适用范围
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

通过 ``/generate``、``/generate_stream``，或透传采样参数的 TGI 兼容接口，
自行设置 ``parameters.guided_reasoning_end``，并实际触发 PD 分段续跑的请求。
该约束涉及自定义标记与历史文本重新编码的兼容性，文本和多模态请求均需遵守。

``/v1/chat/completions`` 由服务端根据 reasoning parser、tokenizer 和 thinking 模式
构造结束标记，不提供这个自定义参数；调用方无需为标准 Chat 请求填写结束 token ID。

约束原因
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

PD Master 保存历史输出文本，续跑时将其拼接到原始 prompt 并重新编码，再重放历史后缀
恢复思考预算和正文约束状态。相同文本重新编码后，不保证仍是原来的 token 序列。
即使 token 数量没有变化，普通 token 构成的自定义结束标记也可能改变。

例如，在已验证的 Qwen3.5-0.8B tokenizer 中，``151668`` 是普通文本 ``خبار``，
标准 ``</think>`` 则是 ``248069``。历史文本中的一段曾出现以下变化：

.. code-block:: text

   原始 token：  [220, 151668]
   重新编码后：  [71787, 148798]

若请求预算为 7、结束标记为 ``[151668]``，历史重放到预算位置时期待 ``151668``，
却读到 ``148798``，就会记录 ``Grammar rejected sampled token 148798``。
这里是历史恢复时的约束拒绝；``148798`` 本身仍是合法词表 ID，词表范围校验无法避免该情况。

失败表现与使用约定
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

* 不兼容时，当前请求可能以 ``finish_reason="error"`` 提前结束，不能视为正常完成。
  该错误由请求内的约束状态捕获和隔离，服务进程可以继续处理其他请求。
* 使用当前模型 tokenizer 对 parser 的标准思考结束序列编码，不要跨模型复用硬编码 ID。
* 任意普通 token 或多 token 自定义序列，不承诺在 PD 文本重编码后仍能正确恢复。
  确需自定义时，调用方应验证其在目标 tokenizer 和历史上下文中的重编码稳定性，
  并覆盖实际分段续跑的场景；只验证单段请求通过并不足够。

该约束保留 native 接口的自定义能力，不要求所有自定义标记都兼容 PD 分段续跑。
