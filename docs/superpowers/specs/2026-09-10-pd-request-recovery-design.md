# PD 请求暂停与 KV 恢复

用户已批准：D 保留原请求及准确 token 历史，容量不足时暂停；本地缓存不足时由 P 补算 KV，不重新接纳生成请求。

## 状态与接口

D 的 InferReq、共享请求、采样 RNG、约束状态、输出计数和 detokenizer 生命周期不变。容量不足进入已有 pause 队列，释放 KV 引用；暂停或恢复传输期间停止接纳新的 D 请求。恢复先匹配本地缓存，足够则直接 decode，否则预留接收空间并向 Master 上报准确 token IDs（不含最后一个待 decode token）。

每次恢复使用递增 epoch；传输键包含 epoch。P 使用独立本地工作 ID，传输目标仍为原 D 请求 ID，完成通知回到各自本地请求。恢复任务不产生对用户可见的 token，不修改 D 的采样状态。真实传输失败终止原请求。

Master 将恢复信息转发给原 P。P 的连接上下文保留原始多模态资源；恢复直接使用 D 的 IDs 和保留的资源，跳过重新分词。P 的工作可排队但不受新请求接纳超时约束，使用现有高优先级调度。P/D 等待受整个请求期限和断连取消约束；已经开始的传输保留原有传输超时。

## 生命周期

P 上的上下文持有一个逻辑请求的资源，单次推理工作额外持有引用。原请求结束、取消、失败或连接断开时关闭上下文，取消补算工作；等待所有共享请求回收后才释放多模态资源。Master 正常结束也发送清理消息。旧分段循环和文本拼接删除。

## 验证与范围

Python 3.10+，不增加依赖。按用户要求不提交单元测试文件。运行现有相关 CPU 测试，并在仓库外验证暂停/恢复、epoch 隔离、资源引用和取消。所有性能或评测实验必须使用 exp；本次不以 CPU 验证代替 GPU 集成验证。
