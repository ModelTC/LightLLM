扩展边界 · 改动发生在哪里

扩展场景主要修改位置继续复用
新模型，沿用已有 attention 和格式ModelAdapter、权重映射、模型计算结构现有 backend、状态存储与传输
新模型，引入新的 attention 机制模型适配、新运算语义与计算实现；按需增加状态格式与恢复能力已有能力与生命周期机制
新 backend，直接消费已有格式probe、批次准备、bind、run 及注册ModelAdapter、存储与传输
新 backend，需要特殊物理格式backend、FormatSpec；按需增加 writer、视图适配、CopyPlan通用 allocator、缓存生命周期与网络驱动
已有模型切换 attention backendPlanner 重新选择与绑定兼容实现模型实现保持稳定

每层声明需求，模型保留计算 recipe

ModelAdapter 可提供专门的计算结构，每层独立声明 AttentionSpec。不同 head 数、维度和 mask 分别匹配；条件相同的层可共享 metadata 与执行实现。

按能力注册与匹配

probe(attention_spec, format_spec, device_caps, limits) 返回支持的执行候选与资源要求，或明确的不支持原因。backend 使用每层规格，避免从整个 model.config 猜测。

绑定时传资源，执行时直接使用

bind(offer, state_view, static_params, workspace) 返回 BoundAttention。静态 scale、常量和 cache view 在此传入；执行不反查 manager。批次适配由 backend 实现，调用时机由 Runner 协调。

布局与阶段约束显式声明

backend 可提出原生布局要求，也可只支持部分阶段。Planner 选择兼容的 prefill、decode、verify 和独立或融合 writer；backend 明确 Graph 固定 buffer、更新规则及必要的动态 planning。
