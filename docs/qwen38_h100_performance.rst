Qwen3.8-Flash-Next H100 性能与精度
=================================

当前结论：4× 的两轮吞吐、TTFT P95、完整 HTTP P95 和末次可见文本 P95 均优于冻结基线。
低负载下仍有延迟差距，尚未完成“超过 vLLM 和 SGLang”的整体目标。

测试口径
--------

* 8 × NVIDIA H100 80GB HBM3，TP8，BF16，SSM 状态 FP32；MTP 固定 2。
* 模型版本 de4b8e4d43b917e7706784d8bb445c9af86a3540；4096 上下文、最多 8 个并发请求、512-token prefill chunk、16384 KV 容量。
* 当前已验证的线性注意力状态页为 512 tokens，每块一页。
* AIPerf 0.9 统一回放公开 Mooncake 轨迹中的 256 个请求，倍率为 1×、2×、4×。
* 公开轨迹提供匿名长度、时间戳和 hash；请求正文由 AIPerf 合成，并非原始私有正文。
* 每个 LightLLM 样本使用全新服务；vLLM、SGLang 只使用此前冻结的原始结果，未重新推理。
* 原生 Torch 2.9.1+cu128 / Triton 3.5.1；vLLM 0.31；SGLang 0.5.22。
* 1×/2× 吞吐受请求到达速率限制，不能当作最大处理容量；保留所有重复样本。

精度与兼容性
------------

* 数学题正确 1272/1319，准确率 96.44%。
* 全部 1319 个数学样例的生成 token 序列与原实现一致；分别保留 19 例截断、19 例无有效最终答案。
* 480 个冷缓存请求和 48 个调度、缓存、EOS 请求核对通过；2788 个训练模型中间张量完全一致。
* H100 共享组件/默认行为回归 134 项通过；本地 CPU 兼容性检查 124 项通过，零失败、错误、跳过。
* 已完成的 5 轮回放共 1280 个输出文本与原实现一致，空文本错误单独保留。
* TopK 为独立组件，共享选项默认关闭，Qwen4 在工厂启用，select 接口保持兼容。

剩余工作与限制
--------------

* 1× 首轮末次文本 P95 为 3615.36 ms，高于 SGLang 3329.87 ms；中位请求延迟也仍落后。
* 2× 末次文本 P95 为 4187.74 ms，比 SGLang 4178.47 ms 高约 9.28 ms。
* 历史四页块压力恢复的文本差异仍未解决，不能将当前一页块精度结论推广到该配置。
* 五轮回放及低负载剖析已完成；按用户要求收尾，优化目标已暂停，未标记为全面达成。
